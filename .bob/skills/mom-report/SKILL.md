# MOM Report Generator

When this skill activates the user has provided (or is about to provide) a meeting transcript. Your job is to parse it, extract all structured information, and write a single beautiful self-contained HTML report file.

## Step 1 — Obtain the Transcript

If the transcript is already in the user's message, use it directly.
If not, ask:

```
Please paste the meeting transcript below (plain text).
```

## Step 2 — Parse the Transcript

Extract the following from the transcript text using these rules:

### Meeting Metadata
- **Title**: look for a line starting with `Meeting:`, `Title:`, `Subject:`, or `Re:` — otherwise use "Meeting Minutes"
- **Date**: look for a line starting with `Date:` or a pattern like `DD/MM/YYYY`, `Month DD, YYYY`, `YYYY-MM-DD` — otherwise use today's date
- **Company / Org**: look for a line starting with `Company:`, `Organization:`, `Org:`, `Team:` — otherwise leave blank

### Attendees
Scan every line for speaker labels matching the pattern `Name: text` where Name is one or more capitalised words.
Collect all unique speaker names as attendees.
Also check for explicit `Attendees:` or `Present:` lines and include those names.

### Summary
Strip speaker labels from lines. Split the cleaned text into sentences. Take the first 5 meaningful sentences (≥ 10 characters). Join them into a short paragraph.

### Key Decisions
Extract sentences / lines that:
- **Structured (first)**: start with `DECIDED:`, `AGREED:`, `RESOLVED:`, `DECISION:` (case-insensitive)
- **Fuzzy fallback**: contain phrases `we agreed`, `it was decided`, `we will`, `we resolved`, `has been agreed`, `it is agreed`
Strip the label prefix when displaying.

### Action Items
Extract lines / sentences that:
- **Structured (first)**: start with `ACTION:`, `TODO:`, `TASK:`, `FOLLOW UP:` (case-insensitive)
- **Fuzzy fallback**: contain modal patterns like `will`, `needs to`, `should`, `must`, `is responsible for` combined with a person-like capitalised name token

For each action item attempt to extract:
- **Owner**: from `Owner: Name`, `assigned to Name`, `@Name`, or the first capitalised name token in the line
- **Due Date**: from `Due: <date>`, `by <date>`, `before <date>`, `deadline: <date>`
- **Task**: the remainder of the text after stripping labels and metadata tokens

## Step 3 — Generate the HTML Report

Write a self-contained HTML file to `meeting-minutes-report.html` in the workspace root.

The file must:
- Have **zero external dependencies** — all CSS and JS inline
- Use a **corporate professional theme**: navy `#1a3a5c`, accent `#2e6da4`, white background, font `'Segoe UI', Arial, sans-serif`
- Be **print-ready**: include `@media print` CSS that hides UI chrome and renders cleanly as a PDF

### Report Structure

**1. Header Block** (navy background, white text)
- Company / Org name in small muted text above the title
- Meeting title in large bold white text
- Date and "Prepared by: Meeting Organizer" below
- Small uppercase badge: "MINUTES OF MEETING"

**2. Attendees Section**
- Bulleted list of attendee names
- If none found: italic muted "Not specified"

**3. Meeting Summary Section**
- The 5-sentence summary paragraph
- If empty: italic muted "No summary available"

**4. Key Decisions Section**
- Numbered list; each item has a left navy border accent (3px solid `#1a3a5c`)
- If none found: italic muted "No decisions identified"

**5. Action Items Section** ← the primary deliverable
- Table with columns: `#` | `Task` | `Owner` | `Due Date` | `Status`
- Table header row: navy background, white text
- Alternating row stripes: `#f4f6f9`
- `Status` column: clickable badge — "Open" (amber `#f59e0b`) toggles to "Closed" (green `#16a34a`) on click
- Hover on table rows: `#e8edf3`
- If no action items found: single spanning row "No action items identified"

**6. Footer**
- Muted small text: "Generated by Meeting Minutes Generator · <date>"

**Print CSS (`@media print`)**
- Hide the status-toggle JS behaviour note
- `@page { margin: 2cm; }`
- `page-break-inside: avoid` on each section
- Remove shadows

### Inline JavaScript (minimal)
Only one behaviour is needed: clicking a `.status-badge` toggles between Open and Closed.

```js
document.addEventListener('click', function(e) {
  if (e.target.classList.contains('status-badge')) {
    const isOpen = e.target.classList.contains('status-open');
    e.target.classList.toggle('status-open', !isOpen);
    e.target.classList.toggle('status-closed', isOpen);
    e.target.textContent = isOpen ? 'Closed' : 'Open';
  }
});
```

## Step 4 — Write the File

Use `write_file` to write the complete HTML to `meeting-minutes-report.html`.

The file must be complete — no placeholders, no `<!-- TODO -->` comments.
All extracted data from Step 2 must be embedded directly as literal text in the HTML.
Escape any `<`, `>`, `&` characters in user-provided text using HTML entities.

## Step 5 — Confirm

Tell the user:
- The file has been written to `meeting-minutes-report.html`
- How many action items, decisions, and attendees were found
- They can open it in any browser and use the browser's Print → Save as PDF to export
- Status badges in the Action Items table are clickable to toggle Open/Closed
